# Cat Food Center

Science-based cat food reviews: scan a barcode or search the catalog to get an ingredient breakdown, additive risk flags, and a 0–100 CFC Score. Plus **The Cat Care Guide** — a free, sourced, eleven-page educational resource on feeding and raising a cat.

**Live site:** https://azqato.github.io/Cat-Food-Center/

---

## Tech stack

| Layer | Tool |
|---|---|
| Pages | Hand-written HTML, plus HTML generated by `tools/learn/` |
| Styling | CSS custom properties (`assets/cfc-tokens.css`) + Tailwind via CDN on four pages |
| Scripting | Vanilla JavaScript, no bundler |
| Fonts | Fraunces, Public Sans (Google Fonts) |
| Generator | Python 3 (developer machines only — never in CI) |
| Hosting | GitHub Pages |
| CI/CD | GitHub Actions, no build step |

**There is no framework and no build step, by decision.** See
[`docs/ADR-001-static-first.md`](docs/ADR-001-static-first.md) for the reasoning, for
why the planned barcode scanner does not need a server, and for the list of
things static hosting genuinely cannot do. A Next.js scaffold used to sit in
this repository unbuilt and undeployed; it has been removed.

## Prerequisites

- **A browser.** Nothing needs installing to view or edit the site.
- **Python 3.8+** — only if you are editing the Cat Care Guide, which is generated.

No accounts, API keys, or environment variables are needed, and there are no
npm dependencies.

## Running locally

The site is static files, so any static server works. From the repository root:

```bash
python -m http.server 8000
```

Then open **http://localhost:8000**.

Opening the `.html` files directly with `file://` mostly works, with two
exceptions worth knowing:

- `fetch` of local JSON is blocked by CORS under `file://`, so anything reading
  from `assets/data/` needs the server.
- The barcode scanner needs a **secure context**. `http://localhost` counts as
  one; `http://<your-LAN-IP>` does not. To test the scanner on a phone, use the
  deployed HTTPS URL or an HTTPS tunnel.

## Commands

| Command | What it does |
|---|---|
| `python -m http.server 8000` | Serve the site locally |
| `python tools/learn/build.py` | Regenerate the eleven Cat Care Guide pages |
| `python tools/check-contrast.py` | Verify both palettes against WCAG AA |
| `python tools/run-tests.py` | Run the test suite headlessly (147 assertions) |
| `python tools/check-live.py` | Eight end-to-end checks against the live API — needs network |
| `python tools/probe-opff.py` | Re-measure the database behind `docs/DATA-COVERAGE.md` |

## Testing

There is no Node.js and no build step ([ADR-001](docs/ADR-001-static-first.md)), so the suite is a page: `tests.html` imports the `*.test.js` modules and runs them in a real browser. `tools/run-tests.py` drives it headlessly and exits non-zero on a failure, which is what makes it usable as a gate.

`tools/check-live.py` is different in kind — it hits the real API, so it is not deterministic and is a smoke check rather than a gate. It renders six page states, walks a recently-viewed round-trip across two page loads, and draws a known EAN-13 to decode it back.

## Environment variables

None, and by design none. Anything shipped to a static page is public, so the
project only uses keyless APIs — Open Pet Food Facts is one. If a future feature
needs a secret, that is a trigger to revisit
[ADR-001](docs/ADR-001-static-first.md), not to add a variable here.

## Deploy

Every push to `main` triggers `.github/workflows/deploy.yml`, which uploads the
repository root to GitHub Pages. It builds nothing, so it cannot fail the way a
build pipeline can — what is committed is exactly what is served.

One-time setup for a new fork:
1. Push the repo to GitHub.
2. Go to **Settings → Pages → Source** and select **GitHub Actions**.
3. The site deploys to `https://<your-username>.github.io/Cat-Food-Center/`.

### Editing the guide

The eleven pages share one documentation shell, so they are **generated** rather than hand-written:

```bash
python tools/learn/build.py
```

Edit the article body in `tools/learn/c_<page>.py` and rerun. `tools/learn/shell.py` owns the shared chrome (top bar, sidebar, breadcrumb, on-this-page rail, pagination, footer) and `tools/learn/bits.py` holds the content components (callouts, tables, entry cards, panels).

Do not hand-edit `learn*.html` — those files are generated and your changes will be overwritten on the next build. The generated output is committed, so **deployment still requires no build step**.

### Shared assets

Everything in [`assets/`](assets/) is loaded by more than one page:

| File | What it is | Loaded by |
|---|---|---|
| `cfc-tokens.css` | The palette (light + dark), the theme toggle, and the chip component | Every page |
| `cfc-theme.js` | Theme switching and persistence. **Must stay a blocking `<script>` in `<head>`** — that is what prevents a flash of the wrong palette | Every page |
| `cfc.css` | The three-column documentation shell | Guide pages |
| `cfc-docs.js` | Mobile drawer and the "on this page" scroll spy | Guide pages |
| `cfc-tailwind.js` | Tailwind CDN theme, mapping colour names to the CSS variables | The four Tailwind pages |

Because the Tailwind colour names resolve to `var(--...)`, Tailwind's opacity
modifiers (`bg-surface/50`) do not work on them. Add a token instead.

## Project status

Live on GitHub Pages, and running on real data. Search and product pages query Open Pet Food Facts and score what comes back; barcode scanning works from the camera or by typing the number. The methodology page, the Cat Care Guide and light/dark theming are complete.

Two things about the data are worth knowing before reading the code:

- **About a fifth of products carry enough data to score all three pillars.** Partial data is the normal path, and the engine returns no score rather than a guess when too little is known.
- **Only about a tenth of records carry English ingredients.** Every text check is therefore a language check; where the label is in a language the aliases do not cover, the engine says so rather than reporting silence as a clean result.

Both are measured, with the method, in [`docs/DATA-COVERAGE.md`](docs/DATA-COVERAGE.md). Next up is offline support. See [`docs/ROADMAP.md`](docs/ROADMAP.md).
